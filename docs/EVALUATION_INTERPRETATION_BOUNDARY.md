# Evaluation Interpretation Boundary

## Output classes

- descriptive outputs
  - `run_evaluation_metrics.json`
  - `condition_evaluation_summary.json`
  - `evaluation_batch_report.json`
- minimal-contrast outputs
  - `condition_comparison_report.json`
  - only for matrix-permitted comparisons with sufficient `n`
- internal support outputs
  - `support_labels.json`
  - `condition_support_labels.json`

## Hard boundaries

- descriptive output is not a theory claim
- minimal contrast is not causal confirmation
- support label is not framework validation
- admissibility is not scientific closure
- runtime evidence is not corpus validation
- no evaluation artifact in this phase is claim-facing safe

## Claim-facing posture

- `run_evaluation_metrics.json`: blocked for claim-facing
- `condition_evaluation_summary.json`: blocked for claim-facing
- `condition_comparison_report.json`: blocked for claim-facing
- `evaluation_batch_report.json`: blocked for claim-facing
- support labels remain internal support layer only

## Interpretation boundary

This phase strengthens internal comparability only. It does not authorize
public-facing or theory-facing over-interpretation.
