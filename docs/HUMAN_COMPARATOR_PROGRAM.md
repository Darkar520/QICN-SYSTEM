# Human Comparator Program

## Purpose

Stage 2 opens the Human Comparator Program only as a formal comparative layer after
`BPF-M3` internal bridge closure. The purpose is to define what would count as a
legitimate human-side comparison target, which burdens must be matched, which
artifact families would later be required, and which inferences remain blocked.

This document does not open a human comparator runtime. It does not create human
datasets, human-channel measurements, equivalence verdicts, or superiority claims.

## Upstream dependence

The program depends on two already-existing conditions:

- subjectivity runtime closure through `SRT-6`;
- bridge internal closure through `BPF-M3`.

These are necessary because Stage 2 compares only against a machine-side layer that
is already formally typed, adversarially stressed, gated internally, and bounded by
non-claims. They are not sufficient because no human-side channel is yet defined.

## Comparator object classes

The Stage 2 comparator ontology uses the following classes:

- `non_comparable`
  - no stable human channel, no homologous measurement contract, or no shared domain.
- `structurally_comparable`
  - bounded structural homology is definable, but no intervention or transport match is yet available.
- `interventional_comparable`
  - matched intervention families and matched controls are definable on both sides.
- `weakly_homologous`
  - descriptive overlap exists, but not enough for strong comparator burdens.
- `comparator_underdefined`
  - comparison language exists, but domain contracts, error budgets, or artifacts remain underdefined.
- `comparator_blocked_by_missing_human_channel`
  - machine-side artifacts exist, but the relevant human-side measurement channel is absent.

These are program-state classes, not verdicts.

## Comparator domains

The formal comparison domains are:

- `bridge_coordinate_domain`
  - future human-side artifacts would be compared to machine-side bridge coordinates under shared typing rules.
- `intervention_response_domain`
  - future human-side intervention signatures would be compared to machine-side intervention signatures under matched control logic.
- `transport_preservation_domain`
  - future substrate-transition artifacts would be compared under preservation and fracture burdens.
- `artifact_lineage_domain`
  - all comparisons must remain schema-typed, provenance-traceable, and version-compatible.

## Comparator burdens

The Human Comparator Program is opened only under explicit burdens:

- `human_channel_burden`
  - no comparator program may proceed without a declared human-side channel, artifact contract, and error model.
- `burden_symmetry`
  - machine-side and human-side comparisons must be burden-symmetric rather than rhetorically convenient.
- `intervention_homology`
  - interventional comparison later requires matched perturbations, matched controls, and bounded channel limitations.
- `traceability_burden`
  - all comparator artifacts must remain lineage-traceable, schema-typed, and surface-restricted.

## Disqualifiers

The following disqualify Stage 2 runtime comparison immediately:

- invented human data;
- hidden equivalence assumptions;
- missing human measurement channels;
- claim-facing surface bypass;
- external adjudication shortcuts.
