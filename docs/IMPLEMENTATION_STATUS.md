# Implementation Status

This inventory tracks `implementation_status` only. It does not encode `run_verdict`, `paper_level_equivalent_status` expressed today as `roeo_enforcement_report.json.batch_status`, or external validation.

Use it together with:

- [DESCRIPTOR_REGISTRY.md](DESCRIPTOR_REGISTRY.md) for formal minimum classification of descriptors, claim projections, gate results, and artifact-only rows.
- [descriptor_registry.v1.json](descriptor_registry.v1.json) and [validate-descriptor-registry.cjs](../scripts/validate-descriptor-registry.cjs) for the machine-validable minimum registry layer.
- [ADMISSIBILITY_GATES_AND_NEGATIVE_CONTROLS.md](ADMISSIBILITY_GATES_AND_NEGATIVE_CONTROLS.md) for the semantics of run-level admissibility, batch enforcement, and negative controls.
- [TRACEABILITY_MATRIX.md](TRACEABILITY_MATRIX.md) for claim-facing linkage between signals, modules, artifacts, and tests.

Normalized status values used below:

- `implemented_tested`
- `implemented_internal_support`
- `partial_runtime_path`
- `compatibility_only`
- `high_risk_control_surface`
- `external_dependency`
- `not_recorded`
