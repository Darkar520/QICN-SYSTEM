# Phenomenal Bridge Interpretation Boundary

## Scope closed by BPF-1

BPF-1 closes only the first runtime-facing bridge layer:

- formal bridge naming remains intact from BPF-0
- machine-readable manifests and schemas remain intact from BPF-0
- six bridge coordinate surfaces now exist
- six run-level bridge reports can now be emitted
- provisional bridge estimators now exist

## Scope not closed by BPF-1

BPF-1 does not close:

- any bridge intervention result
- any bridge comparator result
- any bridge irreducibility result
- any bridge gate verdict
- any bridge support class
- any bridge admissibility class
- any candidate or audit package bridge inclusion
- any Paper 9 burden

## Explicit non-inferences

Nothing in BPF-1 licenses:

- phenomenality
- external validation
- human equivalence
- metaphysical subjecthood
- bridge support
- bridge admissibility
- claim-facing bridge promotion

## Relation to Paper 8

Paper 8 closes first-person indexed subjectivity under its own burdens.
BPF-1 does not reinterpret that closure as phenomenality.

Paper 8 public inclusion in `QICN-RELEASE` does not convert BPF-1 bridge
surfaces into bridge support.

## Relation to candidate and audit packaging

BPF-1 does not authorize bridge artifacts in candidate or audit-facing bundles.
If later BPF blocks expose bridge artifacts there, they must carry explicit
bridge-specific boundaries, non-claims, stale checks, and allow-list changes.

## Reading rule

The strongest legitimate reading of BPF-1 is:

`the bridge program now has provisional runtime-facing bridge surfaces`

The strongest illegitimate readings are:

- `the system now has bridge support`
- `the system now has phenomenal support`
- `Paper 9 is now open`
